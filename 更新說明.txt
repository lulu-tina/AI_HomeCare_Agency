CareFlow 接單、待辦與多段請假更新

安裝
1. 關閉執行中的 Streamlit（Ctrl+C）。備份目前同名程式檔。
2. 將壓縮檔中的 5 個 .py 檔複製到原專案根目錄並覆蓋；dispatch_workflow.py 為新增檔案。
3. 執行 python -m streamlit run app.py，重新整理頁面。

操作
在「臨時異動」選「接單與待辦」：原本各處的派單操作保留，回覆與未解決事項集中於此。
狀態為建議／督導確認／待回覆／已接單／已通知案家。最後兩種需勾選已實際確認並填聯繫紀錄。這是人工登錄，不會發送 LINE、簡訊或電子郵件，也不代表對方已在系統登入回覆。
待回覆人選保留時段；拒接／撤回會釋出人選並轉待安排。換人或改時段後，舊接單狀態失效。
無人可派：點「重新檢查所有候選人」查看每位的阻擋原因；可找前後30／60分鐘時段，需案家同意才套用，最後再次驗證。
可記錄追蹤人、追蹤日期與處理紀錄，逾期會標示。追蹤人由人工填寫，並非登入驗證。
請假：整天或指定多段（每行 HH:MM-HH:MM），可登錄看診、訓練、家庭事務等。重疊或相接區間會合併，與區間重疊的整筆服務轉待安排；界線剛好相接不算重疊。跨日請分日期登錄。
登錄不可排時間會保留到撤銷，排班、插單、改派及固定班延展均讀取此限制。撤銷時段不會自行還原已改派的服務。
原請假頁的逐筆候選面板已整併至接單與待辦，避免兩份重複名單。
失敗的新服務插單會加入待辦；可從待辦找人或協商時間。
月曆卡片與最終派單 CSV 增加接單狀態。

資料
output_results/dispatch_workflow.sqlite3 存放同一資料來源的狀態、不可排時段、未派新增服務及追蹤歷程；請和專案的業務資料一起備份。勿把這個資料庫當作程式碼公開分享。
本次沒有把整個原系統的班表改為資料庫持久化；既有班表及已確認臨時插單仍沿用原本 session 流程。重新載入／重新排班後，以目前班表比對狀態，人選或時段不同即重設；不可把本機追蹤資料庫當成完整班表備份。

驗證
Python 編譯、核心流程測試及原月曆模擬互動測試通過：包含多段合併、邊界、跨日隔離、人員隔離、無效輸入不部分寫入、重複登錄、保存／重讀、來源隔離、狀態失效、待辦新增／移除、拒接釋出、只套用本次及引擎阻擋。
此環境未完成 Streamlit 瀏覽器端到端操作，請在 Demo 前以測試班表彩排。
